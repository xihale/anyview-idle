# anyview-idle

AnyView 自动待机刷时长（accumTime）的小服务：Go 后端 + 纯 HTML 前端（单文件内嵌）。
多账号：每个浏览器一条 cookie 对应一个独立会话，各自登录、各自刷课、状态互不可见；
所有账号的上游请求共享 `-rpm` 全局限速（同一出口 IP 防 WAF 拉黑）。

从 fuckView 的 `idle` 命令拆出，协议细节见 fuckView 仓库 `analysis/02`（登录）、`09`（WAF/XFF）、`10`（计时机制）。

## 用法

```bash
go build -o anyview-idle .
./anyview-idle                # 默认 http://127.0.0.1:8765
./anyview-idle -addr :9000    # 自定义监听
./anyview-idle -rpm 20        # 全局上游限速 (每分钟请求数, 所有账号共享, 默认 20)
```

浏览器打开后：

1. **登录**：学号 + 密码（或直接粘贴已有 token，约 12h 有效）。登录成功即拉取课程配置。
2. **选课程**、填每题目标区间（分钟，默认 5–10）、错误注入区间（次，默认 1–3，0 = 不注入）。
3. **开始**：逐题挂机；**停止**：当前题挂完本轮即收尾。
4. **刷完自动下线**：任务一结束（跑完、手动停止、出错、被踢）即清除本地会话与 token，
   不再占用账号；小结页停留展示。出错中止时先下线让位，默认 3 小时后自动重登续跑
   （下条）；其余情况重新登录即可。

## 错误注入（编译/运行正确错误次数）

compile 接口回 `cmpRightCount/cmpErrorCount`，runGroup 回 `runRightCount/runErrCount`——
即账号侧「编译正确/错误、运行正确/错误」四个计数器。本工具在每题挂完时长后再像真人一样
做 `[下限, 上限]` 次（随机抽）错误尝试：

- 每次尝试随机为两种之一：
  - **编译错误**——用你自己的代码砍一刀（删一个分号/截断），提交编译 → `cmpErrorCount+1`；
  - **编译过但运行错**——直接编译并运行你自己的**未通过代码** → `runErrCount+1`。
- **绝不注入运行正确**：runGroup 全对会判过、改 pass，这不是本工具的事。副作用只有一种：
  你自己的代码本来就是对的（只是没跑过），运行后题目变已通过——这属于意外之喜，日志会点名。
- **存档安全**：compile/runGroup 会顺带把提交代码覆盖到学生存档（analysis/09 实测），
  注入前自动快照 `scheme/list/student/{eid}`，注入后回写 `saveStudentCode` 并读回核对，
  失败重试 3 次、仍不行日志大声告警。
- 实验题（questionType≥3）走另一套 Lab 编译接口，普通接口打不了，自动跳过注入只挂时长。
- 每次尝试间隔 2–5s；注入发生在**该题挂完之后**（401 停止计时 = 前端语义里"打开题目面板"，
  编译只发生在面板打开时，计时阶段保持无打点）。

## 刷机语义

- 目标区间 `[下限, 上限]` 是每题 **accumTime 的目标带**（分钟）。每题在带内随机抽一个目标点：
  - 现累计 **≥ 下限**（已在带内/以上）→ **跳过**，绝不往回刷；
  - 否则从当前值挂到目标点（挂机时长 = 目标点 − 现累计，天然随机）。
- 挂完复核 catalog：accumTime 真涨了才算 done；没涨（实验题 ES 系服务端不计时）会在日志里点名，下轮开刷时按区间重判。
- 已通过题一律跳过——服务端对 pass=true 的题不计时，挂了也是白挂（analysis/10 实测）。
- 换题间隙随机 8–23s，仿人翻题节奏；HTTP 请求每题仅 2 次（刷前确认 + 挂后复核），远低于 WAF 阈值。

## 计时原理（为什么是 WebSocket）

accumTime 唯一来源是 exam WS 的 **401 计时消息对**（HTTP 做题接口一律不计时）：

```
wss://anyview.gdut.edu.cn/api/exam-service/websocket/{token}
{type:401, content:<eID>}  开始给该题计时
{type:401, content:null}   停止
{type:117}                 心跳, 每 40s
{type:206}                 连上先问考试安排（前端行为）
type:119                   token 失效/单点登录被踢 → 本轮中止, 重新登录再开一轮
statusType:403             停留过长 → 断开重连后重发 401 续计时
```

计时器**单活**：服务端同一时刻只记一题，所以逐题串行挂。挂机只动计时器，不碰代码存档、
不触发判题、不改 pass，账号侧无副作用。

## 已知约束

- **会话生命周期**：账号只在配置/刷机期间被持有，任务结束即自动下线（见用法第 4 条）。
  重启时若有未完成任务：token 仍有效则直接续跑（复用自己的会话，不踢人）；
  失效则不重登，进入下条的让位策略。平时重启保持离线，不会顶着你的网页会话互踢。
- **用户优先的让位重登**：任务因 token 失效/被踢/网络问题出错中止时，先下线让位，
  默认 3 小时（`-relogin-wait` 可调）后自动重登并续跑剩余题目；重登撞上网络/服务端
  问题 30 分钟后重试，密码被拒则放弃计划（防连续错锁号）。期间你手动登录或开任务
  即视为接管，自动续跑计划取消。
- token 有效期约 12h（JWT iat/exp），长跑中途 119 被踢无需人工干预——下线让位后
  到点自动续跑，已达标的题自动跳过，不会重复挂。
- 走默认云 WAF 无需额外配置；若 `/etc/hosts` 把域名指到源站直连，登录时必须填
  **X-Forwarded-For**（你的公网出口 IP，登录后不可变），否则网关一律 405/403
  （会话绑定 XFF，见 analysis/09）。
- 密码连续输错有锁号风险（约 3 次），后端不做重试。
- 服务仍只绑本机 `127.0.0.1`，API 本身无鉴权，公开访问须经反代（如 Caddy）暴露。
  会话按 cookie 隔离（sid 为 128bit 随机值，HttpOnly），别人看不到你的账号与进度，
  但**任何能访问到服务的人都能注册自己的会话登录刷课**——不想开放就在反代层加
  `basic_auth` 或访问控制。
- 所有账号共享 `-rpm` 上游限速（默认 20 次/分钟，语义同 anyview-next relay：
  60s 滑动窗口、相邻放行均匀铺开、排队超 20s 放弃报错），账号越多并行开刷
  越容易触顶排队。

## 结构

```
main.go                  HTTP 路由 + 内嵌前端
session.go               多账号会话: cookie 隔离/按会话持久化/让位重登计时
internal/anyview/
  client.go              登录(RSA "密码,时间戳" + multipart)/课程列表(多版本归一化)/catalog
                         /compile/runGroup/代码存档快照与回写
  limiter.go             全局上游限速 (60s 滑动窗口, 所有账号共享)
  timer.go               exam WS 计时器 (401/117/206/119/403, 20s 分片, 断线重连续挂)
  brusher.go             刷机编排: 区间随机目标点/跳过达标/错误注入/复核到账/日志环
web/index.html           纯 HTML 前端, 2s 轮询 /api/status
```
